Guillermo Rauch Vercel CEO

Vercel CEO Guillermo Rauch publishes the only new architecture in today’s feed, and he builds it out of a decomposition. Successful agents — he names Muse, Instinct, OpenClaw and Claude Code — have three parts: "🧠 Brain → model, harness (logic)", "👐 Hands → tools, computer, browser", "🗃️ Files → memories, skills, repos". The easy way is to keep all three in one stateful computer, "a Mac Mini", kept running all day with caffeinate and everything installed on it. Running agents in the cloud cost-efficiently forces them apart: the harness in Fluid compute with its event log made durable via Workflow, the hands as a dedicated browser fleet (Browserbase/Kernel), a computer (Sandbox) or lightweight tools like just-bash. What was missing was the third piece: "Today we’re introducing the perfect companion to Sandbox: Drives... we’re giving you the ‘external disk’ you can attach at will. It’s early, and we’ll be expanding capabilities here quickly." His example is a nightly memory consolidation job that reads and writes files "without ‘booting up’ the agent’s full computer".

Vercel CEO Guillermo Rauch 发布了今天这份 feed 里唯一一套新架构，而它是用一个拆解推出来的。成功的 agent —— 他点名 Muse、Instinct、OpenClaw 和 Claude Code —— 有三个部分："🧠 Brain → 模型、harness（逻辑）"、"👐 Hands → 工具、电脑、浏览器"、"🗃️ Files → 记忆、skills、仓库"。省事的办法是把三样都塞进一台有状态的电脑里，"一台 Mac Mini"，用 caffeinate 让它整天跑着，CLI 和应用都装好。想要在云上低成本跑 agent，就得把它们拆开：harness 跑在 Fluid compute 上，用 Workflow 把事件日志做成持久化的，以应对重启、发布和崩溃；hands 可以是专门的浏览器集群（Browserbase/Kernel）、一台电脑（Sandbox），或者像 just-bash 这样更轻的工具。一直缺的是第三块："今天我们推出 Sandbox 的最佳搭档：Drives……我们给你的是一块可以随意挂载的'外接硬盘'。它还早，我们很快会在这里扩展能力。"他举的例子是一个每晚跑的记忆整合任务，可以直接读写文件，"不用把 agent 的整台电脑'开机'"。

His closing claim is about security rather than cost, and it is the strongest sentence he writes: "breaking apart the agent into these independent parts not only optimizes costs in a big way, it also *massively* improves security and auditability. I’d argue you can’t even run a secure agent otherwise!" No number, no benchmark, no customer is offered for it. It is still the only item today where someone describes how an agent ought to be assembled rather than what one did.

他最后那句主张讲的是安全而不是成本，也是他今天写得最重的一句："把 agent 拆成这些独立的部分，不只是大幅优化成本，它还*极大*地改善了安全性和可审计性。我认为除此之外你根本跑不了一个安全的 agent！"他没有为它给出任何数字、基准或客户。但它仍然是今天唯一一条在描述 agent 应该怎么被组装、而不是某个 agent 做了什么的内容。

His second post is where a model enters, and it is a comparison with no published score: "ShellPerfBench. I’m really neurotic about the startup time of a new shell session. Opus 5.5 found a lot of really great optimizations other models missed." The benchmark is named, the result is asserted, and neither can be checked from here. He closes with a recommendation: "Anon, anytime you open a new terminal, you might be silently suffering. Tell your agent to optimize .𝚣𝚜𝚑𝚛𝚌 and friends"

他的第二条是模型出场的地方，而它是一次没有公布分数的对比："ShellPerfBench。我对新 shell 会话的启动时间非常神经质。Opus 5.5 找到了很多别的模型都漏掉的极佳优化。"基准的名字给了，结果是直接断言的，两者从这里都无法核对。他最后给了一个建议："老兄，你每次开一个新终端，可能都在无声地受苦。让你的 agent 去优化 .𝚣𝚜𝚑𝚛𝚌 和它的朋友们"

Aaron Levie Box CEO

Box CEO Aaron Levie quotes someone at length and endorses it, which makes this the day’s most complete statement about what falling costs do to a creative industry. The passage argues that "as the barriers and the costs come down, more films will get made, not fewer. Studios will get to take more risks. There will be more seats at the table, and very soon entirely new forms of storytelling", and rests it on precedent: animation was "dismissed as a niche corner of the business" in the 1980s and is now one of the most profitable forms of storytelling, and "filmmakers like Steven Spielberg, James Cameron and Peter Jackson embraced new visual tools not as shortcuts, but as instruments, and expanded cinema in the process". Levie does not name the person he is quoting, and the feed does not resolve it.

Box CEO Aaron Levie 大段引用了一个人并背书，这让他给出了今天关于"成本下降会把创意产业变成什么"最完整的一段表述。被引用的那段主张："随着门槛和成本降下来，被拍出来的电影会更多，而不是更少。制片厂可以承担更多风险。桌上会有更多位置，而且很快就会出现全新的叙事形式。"它把论证压在先例上：动画在 1980 年代"被视为行业里一个边缘角落"，如今是最赚钱的叙事形式之一；而"斯皮尔伯格、卡梅隆和彼得·杰克逊这样的电影人拥抱新的视觉工具，不是当捷径，而是当乐器，并在这个过程中拓展了电影"。Levie 没有点出他引用的是谁，feed 也无法解析。

His own addition is about what does not change: "even when the techniques or mediums change, the underlying need for creative skills and taste don’t go away. Read against the enterprise numbers he published in yesterday’s feed — Box measuring Opus 5.5 at 63% fewer tokens and four industry cases — today’s post carries no measurement at all. 他自己补的一句是关于什么不会变："即便技术或媒介在变，对创意能力和品味的底层需求并没有消失。只是当一项新技术到来时，有更多人能有效地用上这些能力，而工具的使用者也会发现讲故事的新方式。"把它和他昨天那份 feed 里的企业数字放在一起读 —— Box 测到 Opus 5.5 token 少 63%，外加四个行业用例 —— 今天这条没有任何度量。是同一个论点，只是被用在了一个他拿不出数据的领域。

Boris Cherny Claude Code, Anthropic

Boris Cherny comes back to the question he asked in yesterday’s feed, and answers a narrower one. On 09-24 he reported formally verifying the Claude Agent SDK with Lean — "16 PRs fixing various bugs and race conditions" — and left it open: "Is formal verification the future of coding (or at least, bug finding)?" Today he publishes what is actually happening instead of ruling on it: "1. Building a model of the program, targeting a tricky state machine or race-prone part of the code / 2. Finding counter-examples in the model. These are suspected bugs / 3. Reproducing the bugs / 4. Fixing the bugs in the code." His own caveat is the part that matters to anyone extrapolating from it: "It’s not that the whole codebase is formally verified (yet!..), more that the hairiest parts of the code are modeled, checked for counter-examples, and fixed." The scope is narrower than the phrase "formal verification" implies, and he is the one drawing the line.

Boris Cherny 回到了他昨天在这份 feed 里提出的那个问题，而回答的是一个更窄的问题。09-24 他报告用 Lean 对 Claude Agent SDK 做了形式化验证——"16 个 PR，修掉各种 bug 和竞态条件"——然后把问题留在那里："形式化验证会是编码的未来吗（或者至少，是找 bug 的未来）？"今天他发布的是实际在发生什么，而不是给出一个判断："1. 为程序建一个模型，针对棘手的状态机或容易产生竞态的那部分代码 / 2. 在模型里找反例。这些就是疑似 bug / 3. 复现这些 bug / 4. 在代码里修掉它们。"他自己的那句限定，对任何想从这里往下推的人来说才是关键："并不是整个代码库都被形式化验证了（还没有！..），更多是代码里最毛糙的那些部分被建模、被检查反例、然后被修掉。"范围比"形式化验证"这个词给人的印象要窄，而划这条线的人正是他自己。

Ryo Lu Designed at Cursor, Notion, Stripe

Ryo Lu, who designed at Cursor, Notion and Stripe, writes the day’s longest post and the only one arguing against the premise the rest of the feed is working from. It opens on the vocabulary itself: "efficiency, productivity, speed / we keep worshipping these words like they are what we live for" — "ship faster / merge more / manage more agents / compress every loop / remove every pause / turn every hour into output" — and then on the question underneath them: "but what is the point of endless production if there is no time left to think deeply?" He is specific about what he means by thinking, and what he excludes from it: "not react / not optimize / not summarize / not clear the queue / think". His account of what AI could be is generative rather than industrial: "ai could be a new canvas / a way to make strange things / personal things / impossible things — tools, worlds, poems, games, interfaces, films, languages, rituals". What he says it is becoming instead is "slop factories... more fake work pretending to be value".

在 Cursor、Notion 和 Stripe 做过设计的 Ryo Lu 写了今天最长的一条，也是唯一一条在反对这份 feed 其余部分所依据的前提。它从词汇本身开头："效率、生产力、速度 / 我们一直像活着就是为了它们一样崇拜这些词" —— "发得更快 / 合并更多 / 管理更多 agent / 压缩每一个循环 / 去掉每一次停顿 / 把每个小时都变成产出" —— 然后是压在它们下面的那个问题："但如果已经没有时间深度思考了，无止境的生产又有什么意义？"他对"思考"是什么说得很具体，也把它排除了什么说清楚了："不是反应 / 不是优化 / 不是总结 / 不是清空队列 / 是思考"。他对 AI 可以成为什么的说法是生成性的，而不是工业性的："ai 可以是一块新的画布 / 一种造出奇怪东西的方式 / 私人的东西 / 不可能的东西 —— 工具、世界、诗、游戏、界面、电影、语言、仪式"。而他说它正在变成的是"slop 工厂……更多伪装成价值的假工作"。

It lands on a reversal, which is the most quotable thing in today’s feed: "the danger is not that ai makes us lazy / the danger is that ai makes us endlessly busy" — "infinite production before we have found intention / infinite execution before we have developed taste / infinite motion before we have learned how to be still". His counter-proposal is a single word rather than a method: "maybe the real frontier is not more speed / maybe it is discernment / knowing what not to make / knowing when to stop / knowing when the most productive thing is to sleep, read history, call a friend, play with a cat, walk without tracking it, or stare at the ceiling until the false urgency dissolves". It closes where it can be argued with: "if ai is going to matter, it should not just help us produce more / it should help us become more human". No company, no product, no number. It still lands on the same fault line that split yesterday’s feed between Levie’s expansion thesis and Thariq’s restraint — argued from outside both companies, and at ten times the length.

它最后落在一个反转上，这是今天这份 feed 里最值得引用的一句："危险不在于 ai 让我们变懒 / 危险在于 ai 让我们无止境地忙碌" —— "在我们找到意图之前就有了无限生产 / 在我们养成品味之前就有了无限执行 / 在我们学会安静之前就有了无限运动"。他的反向提议是一个词，而不是一套方法："也许真正的边疆不是更快的速度 / 也许是辨别力 / 知道什么不该做 / 知道什么时候该停 / 知道什么时候最有生产力的事是睡觉、读历史、给朋友打电话、跟猫玩、不戴 tracker 去走走，或者盯着天花板直到那种虚假的紧迫感散掉"。它收在一个可以被反驳的地方："如果 ai 真的重要，它不该只是帮我们产出更多 / 它应该帮我们变得更像人"。没有公司，没有产品，没有数字。它仍然落在昨天那份 feed 把 Levie 的扩张论和 Thariq 的克制论劈开的那条断层上 —— 只是从两家公司之外来论证，而且长了十倍。

The Takeaway

Yesterday was announcements: Opus 5.5 became the default in Claude Code and the Claude app, and GPT-6 Sol and Luna arrived with a permanent 50% API price cut. Today is the first day of use, and the evidence has a shape worth naming. Every data point about the new models comes from someone running them on their own workload and reporting the result themselves. Swyx switched his own newsletter over after running it against 6 Sol — "night and day", "much less slopese than even 5 Opus" — and he is the publisher of the thing being generated. Rauch reports that on a benchmark he names, "Opus 5.5 found a lot of really great optimizations other models missed". Neither publishes a score. The gap this feed noted on 09-24 has therefore not closed: there is still no independent cross-model number in it, only two more in-house ones.

Boris Cherny answers the question he asked yesterday, and the answer narrows it rather than settling it. On 09-24 he reported formally verifying the Claude Agent SDK with Lean and left it open: "Is formal verification the future of coding (or at least, bug finding)?" Today he publishes the mechanism — model the program, find counter-examples, reproduce, fix — with his own limit attached: "It’s not that the whole codebase is formally verified (yet!..), more that the hairiest parts of the code are modeled, checked for counter-examples, and fixed." That describes what is happening; it does not say whether it generalises. The question he posed is still open, and he is the one who scoped it down.

The case against the day’s premise is written at greater length than the case for it, which is a first for this feed. Ryo Lu argues with the vocabulary itself — "efficiency, productivity, speed / we keep worshipping these words like they are what we live for" — and lands the reversal: "the danger is not that ai makes us lazy / the danger is that ai makes us endlessly busy", closing on "maybe the real frontier is not more speed / maybe it is discernment". Thariq makes the same point in two lines by publishing the input behind an output: "the post: ‘Claude one-shot this’ / the prompt: 10k characters with good takes plus skills, examples and API keys". Peter Yang supplies the gap neither of them names: "one lab has the best model and another has the best harness". Madhu Guru is the only one arguing demand, and he does it by splitting the word consumer in two — browsing clothes is entertainment, hiring a roofer is misery.

Two threads from earlier issues moved today. Muse, which Peter Yang ranked first in the personal agent race on 09-22, picked up two independent signals in one feed — Garry Tan calling it "very impressive" and Levie announcing "Muse and Box, together at last" — so the ranking now has adoption behind it rather than one reviewer’s read. What still does not appear is the consumer agent Nikunj reported as imminent on 09-23. What arrived in its place is another dated commitment from the same person whose last one landed on the day he named: "Can’t wait for DevDay next Tuesday."

核心结论

昨天是发布日：Opus 5.5 成为 Claude Code 和 Claude 应用的默认模型，GPT-6 Sol 和 Luna 带着永久性 50% 的 API 降价而来。今天是使用第一天，而这些证据有一个值得说出来的形状。关于新模型的每个数据点，都来自把它跑在自己的工作负载上、然后自己报告结果的人。Swyx 拿它和 6 Sol 并排跑完之后把自己的 newsletter 换了过去 —— "差别是白天和黑夜"、"连比 5 Opus 都少了很多 slopese" —— 而他是被生成的那个东西的发布方。Rauch 说在一个他点名的基准上，"Opus 5.5 找到了很多别的模型都漏掉的极佳优化"。两个都没有公布分数。所以这份 feed 在 09-24 指出的那个缺口并没有补上：里面仍然没有一个独立的跨模型数字，只是又多了两个自家跑的。
